# Handoff / 交接提示词：<task-id>
最后修改时间: 2026-10-13 10:44:07

用户要求交接时填写实际值；有 task 时先按协作契约登记有效分配，无 task 时引用父级计划并注明编号等字段不适用。

```text
按 SpecFlow 完成本次授权范围内的工作，先读取并核对：
- 协议入口：<可读的 SKILL.md 与协作契约位置>
- 总意图：<实际路径>
- 权威协调根与总计划：<实际位置，不以分支副本授予执行权>
- 任务文档与 ID：<实际路径、T01；无 task 时使用父任务标识>
- 执行者、分配编号与方案修订：<权威登记中的实际值>
- 授权来源、阶段与范围：<用户指令依据及总计划记录位置>
- 代码工作区、基线与前置交付：<实际版本、产物和检查及接受证据>
- 目标、验收与修改约束：<交付结果、验收 ID、非目标、隔离和集成要求>
- 可写回报位置及主会话读取方式：<task 或已有计划的实际路径与章节>

1. 核对当前方案、授权、分配、输入版本及记录可读可写性。缺失、冲突或失效时回报并暂停，不自行补造授权或修改归属；有效授权可以沿用。
2. 产品修改前，写入接收时间、执行者、编号、方案修订、授权和实际基线，输出接收摘要。成功写入后按授权工作，无需等待登记同步；写入失败先解决记录位置。
3. 按方案完成授权工作，记录关键进展和阻塞。新增需求疑问或设计缺口时暂停受影响部分，回报主会话并按阶段规则补齐。
4. 宣布交付前，写完整变更、验收证据、版本、前置输入、检查及未完成项与风险。写入失败时说明“交付记录未完成”，提供待补内容。
5. 接收后、需仲裁时及交付时，输出可复制摘要：任务 ID、编号、事实、记录位置与版本、检查及风险、请主会话处理的事项。默认由用户转交，写文档不会自动通知其他会话。

总登记与交付接受由主会话按证据维护，执行者只回报事实。无 task 时使用已有计划的约定章节，不建立登记表。完成本次授权后交付结果，不额外启动执行者、通知渠道、Git 写入或发布。
```
