# Handoff / 子任务交接提示词：<task-id>

最后修改时间: 2026-10-10 21:25:56

仅在用户要求派发、仲裁会话核对可分配条件并登记有效分配后，填写以下提示词。默认交给用户可见的独立会话；提示词生成只表示已安排责任。无 task 时可以直接引用意图和计划，不另建任务文档。

```text
依据 SpecFlow 的统一流程，在以下授权阶段与范围内完成本次任务。
父任务流程为 Intent → Plan → Implementation → Verification。

你是本任务的执行会话。先读取并核对以下实际记录：
- 权威协调根：<所有执行会话能读取的位置>
- 总意图：<实际路径>
- 权威总计划：<实际路径；不使用其他分支的副本授予执行权>
- 子任务文档：<实际路径；无 task 时引用总意图和总计划>
- 任务 ID：<T01；无 task 时使用父任务标识>
- 执行者代号：<本次分配的执行者>
- 分配编号：<仲裁会话已登记的唯一编号；无 task 时写不适用>
- 方案修订：<本次分配依据的方案版本>
- 用户授权阶段与范围：<实际授权及指令依据>
- 代码工作区与基线：<实际位置、版本及必要的已接受交付>
- 前置交付及证据：<版本、所需产物、检查和接受记录>
- 目标与验收：<本次交付及验收 ID>
- 允许修改与共享约束：<范围、非目标、隔离和集成要求>
- 接收、进展和交付记录位置：<实际位置>

确认总计划中的分配编号、执行者、方案、阶段和前置条件仍有效，
并且所需交付能用于你的工作基线。核对失败时回报仲裁会话，
不要通过自行改写任务归属取得执行权。

在约定位置记录接收、工作基线、进展和阻塞。用户可以在本会话直接
与你沟通。涉及任务边界、依赖、共享契约或额外目标时，回报主会话
协调；不要静默扩大变更。只执行上述实际授权的阶段与范围。

提交实际变更、可访问的交付版本或 diff、使用的前置版本、必要检查
结果、未运行项及风险。由主会话 review 后更新任务登记并放行下游。
若只授权 Implementation，完成局部检查和交付后等待后续安排；
生成本提示词不等于授权自动调用更多执行者、提交、推送或发布。
```
